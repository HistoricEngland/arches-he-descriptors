# Arches HE Descriptors 1.0.0rc1

First PyPI release candidate. Development Status: **Beta**.

## Included

- Graph-specific YAML configuration for resource display names, descriptions
  and map popups.
- Rule priorities, required-field fallbacks, defaults, formatting and text
  operations.
- Django admin configuration editors and descriptor preview/API endpoints.
- Arches primary descriptor function integration and the initial configuration
  model migration.
- Installation, configuration and implementation guides.
- Python package discovery includes application subpackages and runtime assets;
  distribution archives exclude tests, local settings, workflows, webpack
  tooling and release notes.
- A GitHub release-created workflow for subsequent trusted PyPI publication.

## Requirements and integration

- Python >=3.10, within the versions supported by the host Arches release.
- Arches >=7.6.17, <7.7.0; PyYAML >=6.0.
- A configured Arches project with its database, search and front-end services.

After the candidate is published on PyPI, install it explicitly:

```bash
python -m pip install arches-he-descriptors==1.0.0rc1
```

Follow the [installation instructions](../README.md#integrating-into-an-existing-arches-project)
to configure application discovery and URLs, apply migrations, register the
function, assign it to a graph and build the host project's front end.
Installation alone does not perform these integration steps.

The Python distribution version is `1.0.0rc1`. Arches' `APP_VERSION` retains
its `semantic_version.Version` type and represents the same candidate as
`1.0.0-rc1`, also the npm version. These spellings normalize to the same
PEP 440 version.

## Candidate limitations

- This is a pre-release, not a production/stable compatibility certification.
- Saving configuration does not regenerate stored resource descriptors.
- See the [implementation guide](../docs/IMPLEMENTATION_GUIDE.md) for current
  API contracts, limitations and integration-test fixture caveats.
- Python and npm licence declarations are unchanged pending maintainer
  confirmation of the existing AGPL-or-later versus AGPL-only discrepancy.

## First-publication checklist

Do not upload until the candidate and its version have been approved. A PyPI
version cannot be reused even after deletion. Use only freshly built artefacts;
do not upload unrelated files from an old `dist/` directory.

1. Confirm `1.0.0rc1` is unused in PyPI and GitHub releases, and that the release
   commit contains these notes, version metadata and the publishing workflow.
2. Run the pinned Black formatter (`black==24.4.2`) on all tracked Python files,
   verify dependency constraints, build with `python -m build`, inspect both
   archives for the required contents/exclusions, and run
   `python -m twine check --strict dist/*`.
3. Register the PyPI pending GitHub publisher:
   project/repository `arches-he-descriptors`, owner `HistoricEngland`,
   workflow `publish-to-pypi.yml`, environment **blank**.
   The owner is the GitHub organisation, not a PyPI organisation.
4. Publish the checked candidate manually with `python -m twine upload dist/*`.
   Supply the PyPI token through Twine's secure prompt or an approved credential
   store; never put it in the repository, chat or shell command arguments.
5. Confirm `1.0.0rc1` is visible on PyPI. Add `aj-he` and `csmith-he` as project
   **Owners**, and confirm both invitations have been accepted. Verify that the
   trusted publisher is configured on the created project; do not assume a
   pending entry was activated by the manual Twine upload.
6. Create the matching GitHub tag and release `1.0.0rc1` from the approved
   release branch and mark it **Pre-release**, not Latest. Use the candidate
   notes above as the release body, without internal work-item references.
   Temporarily disable the publishing workflow for this first GitHub release,
   since its version was already uploaded manually; re-enable it afterwards
   for subsequent releases. Otherwise it attempts a duplicate upload.
7. Install `arches-he-descriptors==1.0.0rc1` from PyPI into a clean Arches project.
   Complete the integration steps, configure a graph and verify display names,
   descriptions and map popups, including stored descriptor regeneration.

The checklist records required actions, not evidence that publication,
ownership or clean-project integration has already been completed.
